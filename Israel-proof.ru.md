# Шесть возможных позиций в перестановке Кимберлинга

Для каждого целого \(v>1\) его позиция \(T(v)\) в A050128 принадлежит списку

$$v/2,\quad v+1,\quad 2v+2,\quad 2v+3,\quad 4v+3,\quad 4v+5.$$

Первый вариант возможен только для чётного \(v\). Это гипотеза Роберта Израэля от 18 февраля 2020 года. Например, число 81 стоит на позиции 329, поэтому последний вариант действительно нужен. [Гипотеза A050129](https://oeis.org/A050129/internal) · [Определение перестановки A050128](https://oeis.org/A050128)

## От исходного правила к семи позициям

Пусть \(a_1=1\). На шаге \(i\ge2\) алгоритм пробует \(h=\lfloor a_{i-1}/2\rfloor\). Если \(h>0\) и ещё не встречалось, он записывает \(h\). Иначе он записывает \(2i\). Отсюда \(a_i\le2i\), а выбранное значение всегда новое. Если значение \(x\) уже появилось к шагу \(t\), то его положительная половина \(\lfloor x/2\rfloor\) появится самое позднее к шагу \(t+1\).

Этого достаточно, чтобы по индукции получить \(T(v)\le4v+5\). Если \(v\) всё ещё отсутствует к шагу \(4v+5\), то на шагах \(i=4v,4v+1,4v+2\) нельзя было выбрать \(2i\). Три последовательных применения свойства половины гарантировали бы появление \(v\). Значит, на всех трёх шагах происходило деление. В результате на шаге \(4v+2\) появилось положительное \(m\le\lfloor(8v-2)/8\rfloor<v\). По индукции оно уже встречалось к шагу \(4m+5\le4v+1\), что невозможно. Случай \(v=1\) задан явно.

Если проследить первое появление \(v>1\) назад до последнего выбора \(2i\), между ними будет от нуля до трёх делений. Четыре деления потребовали бы \(16v\le2(T(v)-4)\), что противоречит полученной границе. Расписав четыре случая, получаем шесть позиций из гипотезы и ещё одну возможную позицию \(4v+4\). Эта часть уже была в предыдущей работе. [Проверка исходного правила и оценки](DoubleHalf.lean) · [Предыдущая версия результата](https://github.com/insorrowmeow/oeis-sequence-proofs/blob/main/DoubleHalf.lean)

## Как исключается седьмая позиция

Пусть \(n>1\) — наименьшее исключение. Тогда \(a_{4n+4}=n\). Для всех \(v<n\), \(v>1\), позиция \(4v+4\) уже исключена. Обозначим через \(C(v,t)\) высказывание \(a_t=v\). Любое исключение должно одновременно удовлетворять следующим правилам.

1. Для каждого \(v>1\) истинна одна из клеток \(C(v,t)\) в разрешённом списке позиций. Для каждого \(t>1\) тоже существует клетка \(C(v,t)\) с \(v>1\) из этого списка.
2. Две разные позиции одного значения несовместимы. Несовместимы и два разных значения в одной позиции.
3. Если \(C(v,t)\), \(C(w,u)\) и \(w\) равно \(2v\) или \(2v+1\), то \(t\le u+1\). Это свойство положительной половины, доказанное выше.
4. Если \(C(v,t)\), \(t>1\) и \(v\ne2t\), то на шаге \(t\) произошло деление. Поэтому истинна одна из двух клеток \(C(2v,t-1)\), \(C(2v+1,t-1)\).

Каждое правило выведено в Lean из определения \(a_t\). Для малых \(n<32\) ядро проверяет начальные значения по тому же определению. [Правила для клеток](InverseBase.lean) · [Начальный случай](InversePrefix.lean)

Для \(n\ge32\) таблица даёт семь исчерпывающих случаев. В каждой строке \(k\) — **произвольное** неотрицательное целое. Правый столбец показывает, сколько условий, включая \(C(n,4n+4)\), достаточно для противоречия.

| Значение \(n\) | Число условий |
|---|---:|
| \(32+4k\) | 81 |
| \(34+4k\) | 81 |
| \(33+8k\) | 215 |
| \(37+8k\) | 215 |
| \(39+8k\) | 70 |
| \(35+16k\) | 138 |
| \(43+16k\) | 138 |

Для построения таблицы мы искали конфликт между клетками, чьи координаты близки к удвоенным или уполовиненным индексам. Затем оставили условия, участвующие в выводе противоречия. Для каждой такой клетки обе координаты записаны как \(Ak+B\). Lean отдельно доказывает каждое использованное условие при произвольном \(k\), а затем собирает из них противоречие средствами логики. Например, [случай \(n=39+8k\)](P8R7.lean) содержит все 70 условий и полный вывод. Итоговая теорема объединяет семь случаев сильной индукцией. [Теорема israel_A050129](Israel.lean)

## Воспроизведение

Все теоремы о A050129 используют стандартную библиотеку Lean 4.19.0. Включённый архив содержит также автономный проект в папке inverse.

~~~sh
lake build Israel
python verify_inverse.py
~~~

Первая команда собирает формальное доказательство. Список аксиом итоговой теоремы равен [propext, Classical.choice, Quot.sound]. Вторая команда независимо проверяет допустимость линейных ограничений, все логические сертификаты и покрытие классов по модулю 16. Для неё достаточно стандартной библиотеки Python и архива сертификатов в этой папке. [Проверяющий скрипт](verify_inverse.py) · [Сертификаты](residue-certificates.zip)

Поиск по номеру последовательности и формулировке нашёл исходную запись Израэля. Более раннего полного доказательства при этой проверке обнаружить не удалось.
